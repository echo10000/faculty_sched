# Phase 4 manual timetables implementation plan

Goal: implement the owner's Phase 4 specification only, preserving the 134 existing tests and all prior data/migrations.

Architecture: a `timetabling` app reuses academic terms, rooms, faculty availability and teaching assignments. Legacy scheduling remains untouched. Weekly meetings derive faculty/offering from their teaching assignment; a one-to-one OfferingRequirement supplies a term/department-compatible ClassSection and optional room requirements. Schedule is a departmental workspace with DRAFT/VALIDATED state. Conflicts are computed, not persisted.

## Decisions

- ClassSection optionally references existing Program; no enrollment/student coupling.
- ScheduleEntry has schedule, assignment, room, weekday, times, meeting type and notes. Academic term, faculty, offering and section are derived.
- RoomUnavailability is term-specific and weekly. Room selection preserves current ownership permissions; institution-wide booking eligibility is not invented.
- Cross-workspace overlaps are checked, including overlapping term date ranges with an actual common weekday. Draft workspaces reserve resources in Phase 4; alternatives/versioning are deferred.
- Structured Conflict results have code, severity, entry references, message and remedy. Canonical services accept unsaved candidate entries independently of forms.
- A PostgreSQL transaction advisory lock serializes timetable mutations and validation; final saves always recalculate. This deliberately favors correctness over throughput. No solver or publishing.
- Schedule mutations reset DRAFT; dependency fingerprints prevent displaying stale VALIDATED status after resource/availability/requirement changes. Whole-schedule validation includes required weekly meeting-hours coverage, reported as warnings because no institutional completeness hard rule was supplied.
- Sparse AVAILABLE records are informational; only UNAVAILABLE blocks. PREFERRED is nonblocking. Capacity defaults to warning; mandatory room types block. Workload is displayed but not incremented by meetings.
- Conflicts involving another organizational scope are reported without its private titles/names/IDs.
